⚙️ Nœud A · coordinateur · campagne CH3/S4

Installer le kit de mesure
sur ton PC Windows

Cette page installe le minimum pour jouer le rôle de nœud A (coordinateur) dans la campagne de mesure QUIC/mTLS entre deux machines réelles (protocole). Chaque bloc se copie en un clic ; l'étape finale vérifie chaque paquet automatiquement.

1

Prérequis — les paquets

Git, Rust 1.91+, Python 3 et les platform-tools Android (adb). Installe ce qui manque, puis passe au bloc suivant.

# Git for Windows (si absent) — https://git-scm.com/download/win # Rust (si absent) : winget install Rustlang.Rustup rustup default stable rustup target add wasm32-unknown-unknown # Python 3 (si absent) : winget install Python.Python.3.13 # platform-tools (adb) : winget install Google.PlatformTools
Le NDK Android n'est nécessaire qu'à l'étape 3 (compilation croisée du binaire du téléphone). Si tu as Android Studio, il est probablement déjà dans %LOCALAPPDATA%\Android\Sdk\ndk.
2

Cloner le dépôt et compiler le binaire du PC

Dans PowerShell (ou Git Bash) :

git clone https://github.com/Geoking2104/AInonymous.git cd AInonymous cargo build --release -p relay-quic-spike
Résultat attendu : target\release\quic-spike.exe. Premier build : quelques minutes.
3

Compiler le binaire du téléphone (Android)

Dans Git Bash, depuis la racine du dépôt. Le script trouve seul le NDK (ANDROID_NDK_HOME ou le dossier SDK) :

bash scripts/campaign/cross-compile-android.sh
Résultat : dist\android\quic-spike (binaire aarch64 du téléphone) + dist\android\SHA256SUMS.
4

Préparer le téléphone connecté

Active le débogage USB sur le téléphone, branche-le, puis dans Git Bash :

bash scripts/campaign/android/prepare-device.sh

Le script installe Termux si besoin, pousse le binaire + les scripts vers le téléphone et établit la redirection tcp:7700. Ensuite, sur le téléphone, suis la page Android (nœud B).

✓

Vérifier l'installation

Lance le vérificateur, copie sa sortie complète, et colle-la ci-dessous :

powershell -ExecutionPolicy Bypass -File scripts\campaign\check-windows.ps1
▶

Tout est vert ? Lance la campagne

# worker démarré sur le téléphone (voir page Android) : python scripts/campaign/run-campaign.py --links usb,wifi --runs 3 --hardware "PC <modèle> + téléphone <modèle>" # puis consolider les résultats : python scripts/campaign/aggregate-results.py
⚙️ Node A · coordinator · CH3/S4 campaign

Set up the measurement kit
on your Windows PC

This page installs the minimum needed to act as node A (coordinator) in the real two-machine QUIC/mTLS measurement campaign (protocol). Every block is one-click copyable; the final step verifies each package automatically.

1

Prerequisites — the packages

Git, Rust 1.91+, Python 3 and the Android platform-tools (adb). Install what is missing, then move on.

# Git for Windows (if missing) — https://git-scm.com/download/win # Rust (if missing): winget install Rustlang.Rustup rustup default stable rustup target add wasm32-unknown-unknown # Python 3 (if missing): winget install Python.Python.3.13 # platform-tools (adb): winget install Google.PlatformTools
The Android NDK is only needed at step 3 (cross-compiling the phone binary). If you have Android Studio, it is probably already in %LOCALAPPDATA%\Android\Sdk\ndk.
2

Clone the repository and build the PC binary

In PowerShell (or Git Bash):

git clone https://github.com/Geoking2104/AInonymous.git cd AInonymous cargo build --release -p relay-quic-spike
Expected result: target\release\quic-spike.exe. First build: a few minutes.
3

Build the phone binary (Android)

In Git Bash, from the repository root. The script locates the NDK by itself (ANDROID_NDK_HOME or the SDK folder):

bash scripts/campaign/cross-compile-android.sh
Result: dist\android\quic-spike (the phone's aarch64 binary) + dist\android\SHA256SUMS.
4

Prepare the connected phone

Enable USB debugging on the phone, plug it in, then in Git Bash:

bash scripts/campaign/android/prepare-device.sh

The script installs Termux if needed, pushes the binary + scripts to the phone and sets up the tcp:7700 forwarding. Then, on the phone, follow the Android page (node B).

✓

Verify the installation

Run the checker, copy its full output, and paste it below:

powershell -ExecutionPolicy Bypass -File scripts\campaign\check-windows.ps1
▶

All green? Run the campaign

# worker started on the phone (see Android page): python scripts/campaign/run-campaign.py --links usb,wifi --runs 3 --hardware "PC <model> + phone <model>" # then consolidate the results: python scripts/campaign/aggregate-results.py
