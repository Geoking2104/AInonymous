# Integrating HybridNode into Another Project

HybridNode is reusable as a configuration, identity and scheduling layer. It does not turn an application into a secure distributed inference system by copying one file; the host must preserve the control-plane/data-plane identity binding and deployment constraints below.

## Compatibility

Use exactly this Holochain family:

- conductor and `hc` 0.7.0;
- `holochain_client` 0.9.0;
- HDK 0.7.0 and HDI 0.8.0;
- Lair 0.7.1.

## Generate a configuration

```bash
bash scripts/hybridnode/init_project.sh my-project
python scripts/hybridnode/validate_config.py my-project/hybridnode.yaml
```

For a private deployment, start from the private mode generated by the script, provide real internal bootstrap/relay settings, configure non-mock SD-WAN if required, and run:

```bash
python scripts/hybridnode/validate_config.py --production my-project/hybridnode.yaml
```

## Add the Rust layer

Either consume `hybridnode-core` from this workspace or publish/pin it from a reviewed Git revision. The host process should:

1. deserialize `HybridNodeConfig`;
2. call `validate()` before opening sockets;
3. connect to the local Holochain 0.7 admin interface;
4. issue an app token and connect to the app interface with `ClientAgentSigner`;
5. obtain the provisioned cell's agent public key;
6. initialize QUIC transport identity and announce its public key;
7. initialize topology/scheduler adapters;
8. start health/metrics interfaces on protected addresses.

Never derive a QUIC private key from, or attempt to export, the Holochain agent key.

## Install the hApp

Build `dnas/hybridnode` for `wasm32-unknown-unknown`, pack it with `hc` 0.7.0, and install it under the same `app_id` used by the host configuration.

For private mode, set DNA properties before packing:

```yaml
properties:
  private_network: true
  network_id: "your-unique-network-id"
  network_admin_pubkey: "<administrator AgentPubKey>"
```

Create a proof for the exact joining agent and network ID, serialize it, and pass it as the role's membrane proof during installation. Do not add membrane proofs to application messages or zome-call JSON.

## Preserve transport-key binding

The host application's capability entry must include the QUIC Ed25519 public key. Session negotiation must read the actual Holochain call provenance and confirm that the caller authored the matching key before the receiver pins it. Treat any missing/malformed/mismatched key as a hard failure.

## Deployment checklist

- [ ] All Holochain artifacts match the pinned 0.7 compatibility matrix.
- [ ] A fresh conductor data root is used; no 0.6 database is reused.
- [ ] Admin WebSocket is loopback-only and distinct from the app port.
- [ ] Holochain agent keys remain in Lair.
- [ ] QUIC private keys use a native secret store.
- [ ] Strict peer-key verification and SD-WAN TLS verification are enabled.
- [ ] Private network ID and bootstrap/relay infrastructure are deployment-specific.
- [ ] Public-network mode is not represented as Sybil-resistant.
- [ ] Local HTTP/metrics endpoints are isolated or authenticated.
- [ ] Failure, relay and peer-churn tests pass in the target environment.
